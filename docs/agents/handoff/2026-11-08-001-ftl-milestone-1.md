# Handoff: Faster than Lumos, milestone 1 (2026-11-08)

## What was accomplished

Greenfield build of **Faster than Lumos** (FTL): an original, multiplayer-focused, browser-based game with
real-time ship combat in the spirit of *Faster Than Light* (2012). The user's brief: a server, an HTML
client over WebSocket, and an AI opponent to fight, built "the most general way"
("elegance beats dogged determination", now in `CLAUDE.md`).

Milestone 1 is done and verified:

- **Play it:** `npm install && npm start`, open `http://localhost:8080` (port via `PORT`). Menu offers
  Fight the AI (4 difficulties), Duel a friend (pvp code), Watch two AIs, Join/Spectate by code, and
  "Play offline in this browser" (`?local`: the whole host runs in the page).
- **Combat:** two original ships (Candlewick, Lampblack), reactor power routing across Helm/Shields/
  Engines/Weapons, four original weapons (Flint Bolt, Ember Volley, Long Needle = missile-like pierce,
  Hush Pulse = ion), shield layers and regen, evasion rolls, system damage, crew who walk, man stations
  and repair, hull and crew loss, Victory/Defeat, Rematch.
- **Multiplayer:** authoritative server, co-op (several humans per ship), pvp, spectators, reconnect by
  token (sessionStorage), per-perspective redaction of enemy intent.
- **Tests:** `npm test` 274 unit/sim/host/AI/ws tests in about 5 s; `npm run test:e2e` 8 headless
  Chrome scenarios (desktop, phone portrait/landscape, tablet, small landscape, co-op, outcome,
  unreachable server) writing screenshots to `test/artifacts/` (gitignored).
- **Balance:** `node tools/duel.js candlewick lampblack --ai captain --games 200 --threads 8` gives
  Candlewick about 59 to 60 percent in either ship order, fights about 118 s simulated.

Files: `shared/sim` (19 files, pure integer sim), `shared/content` (data + `validate.js`),
`shared/ai` (estimate, brain, occupant), `shared/net` (protocol, link), `shared/host` (clock, presets,
match, session, lobby, replay), `server/` (main, static, ws-link), `client/` (13 files, zero-build ES
modules), `tools/duel.js`, `test/` (24 test files + `helpers/cdp.js`, `helpers/fixtures.js`).

## How it was built (process)

All via ultracode workflows:

1. **Design panel:** three architects (simulation-first, multiplayer-first, minimalist) proposed
   independently; a judge synthesized `docs/design.md` (the contract, about 2100 lines, kept truthful by
   later passes). Saved as a reusable workflow at `.claude/workflows/ftl-design-panel.js`.
2. **Build:** sim+content first, then AI, host/server, client in parallel, then an integrator.
3. **Adversarial review:** four finders (sim, host/security, client/UX, elegance), one skeptic per area,
   one fixer. 26 of 28 findings confirmed and fixed with regression tests (notably: a malformed ws frame
   or a deeply nested command could crash the server; replay diverged after pause; pvp seeds were
   predictable; public match list let strangers take crew seats; several phone-layout and reconnect bugs).

## Key decisions

- **`step(world, commands) -> events`** is pure, deterministic, integer-only plain JSON. No clocks,
  timers or `Math.random` in `shared/sim`, `shared/ai`, `shared/content` (enforced by `test/purity.test.js`).
- **Everything that progresses over time is a Meter `{v, max, rate}`** (`max = ms * 100`). Clients
  extrapolate meters from the latest 10 Hz snapshot (at most 250 ms); no interpolation buffer.
- **One stats fold:** `computeStats(ship)` is the only place modifiers combine. The helm's evasion rule
  became pure data (`unmanned` tables), so `SYSTEM_HOOKS` currently has no entry.
- **Power:** commands set intent (`want`, `on`); `settlePower` is the only writer of actual power.
  Damage/ion free bars at once; restoration only from free bars.
- **Hit pipeline:** evasion roll, then `shield.v > bp.pierce` blocks (pops one layer, applies `onBlock`),
  else `onHit` through the `EFFECTS` registry. Weapon types differ only by data.
- **Commands are absolute idempotent setters** (`setPower`, `setDevicePower`, `setTarget`, `setAuto`,
  `moveCrew`); humans and AI use the same vocabulary and authorization. Host stamps `ship`.
- **AI is a player without a socket:** it receives the identical projected snapshot string a human on its
  side gets, synchronously, and scores counterfactuals on cloned views with the sim's own helpers (it
  values stats, not system names). Difficulty is data in `content/ai-profiles.js`.
- **Link abstraction** (text pipe) lets the same Lobby run behind `ws` in Node or in-memory in the browser.
- **Zero build, one runtime dependency (`ws`), JSDoc + `// @ts-check`.** No `@types/node`, so
  `npm run check` reports only missing Node typings in server/test/tools (expected).
- **Ruled out for M1:** delta snapshots, client prediction, binary encoding, accounts/persistence,
  oxygen/fire/breach/doors/medbay, beams/drones/boarding, sectors/events/stores, PWA/Capacitor
  (design.md 21.2 lists them and 21.1 says where each lands).

## Important context for future sessions

- **Read first:** `CLAUDE.md` (principle + architecture rules), then `docs/design.md` sections 1 to 5,
  then the section for the area you touch. Keep design.md truthful when behavior changes.
- **Git:** repo initialized on `main`, **nothing committed yet** (the user has not asked for commits).
  User preference: never add Co-authored-by lines to commit messages.
- **Originality rule:** names, ships, weapons, text, art and UI look must be our own (visual identity is
  "power is light": deep ink, luminous procedural line art, amber power glow, cyan shield halos).
- **No em dashes or en dashes** in user-facing text (user's global rule).
- **Open items / known issues** (also design.md section 22):
  - Seating has no consent step: anyone holding a code can take a free seat (a `grant` match action is
    the planned fix). No per-address connection cap yet.
  - Novice vs novice is lopsided (Candlewick about 97 percent) because novices never sync volleys;
    captain and ace are balanced. Tune via content data and `tools/duel.js`.
  - Not yet tested on real phones or iOS Safari (only Chrome device emulation).
  - The e2e co-op scenario flaked once; a wait-for-HUD fix was added but the root cause is unconfirmed.
  - Chrome "Duplicate tab" copies sessionStorage, so two tabs can share one player token.
- **Process hygiene:** e2e tests launch headless Chrome with a `ftl-chrome-*` temp profile; one was left
  running by a review agent this session and was killed. Check `pgrep -fl ftl-chrome` if things act odd.
- **Natural next steps:** play a full fight by hand and tune feel; doors/oxygen/fire (room state + room
  statuses), a medbay (first `SYSTEM_HOOKS` entry), a beam delivery, more ships, an enemy-ship picker
  in the menu, consent-based seating, PWA manifest for phones.
